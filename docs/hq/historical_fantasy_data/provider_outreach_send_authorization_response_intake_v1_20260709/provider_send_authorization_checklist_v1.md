# Provider Send Authorization Checklist V1

Use this checklist before any route-feed outreach is sent.

## Required Human Approval

No outreach may be sent until all are true:

- NWR owner approves sending.
- Provider target is selected.
- Contact name/email is verified.
- Message body is reviewed by NWR owner.
- No raw provider data is requested in the first message.
- No private-account or paywalled access is requested.
- No scraping, bypass, or client-object use is implied.
- Source-admission caveat is preserved.
- Legal/contract owner is identified if provider requires paid terms.
- Response intake owner is assigned.

## Message Checks

Confirm the draft asks for:

- actual player-level `routes_run`
- WR/TE/RB coverage
- season grain at minimum
- week/game grain if available
- stable player identity field
- player name
- team
- season
- position
- provider/feed name
- source update timestamp
- field dictionary
- historical coverage range
- update cadence
- missingness documentation
- reproducible API/export/static path
- allowed storage and derived-metric use
- redistribution/storage restrictions
- checksum/provenance support

## Prohibited Before Sending

Do not:

- attach NWR source-truth files
- attach raw provider data
- ask provider to send raw player rows before safe intake is approved
- imply NWR will use data without source admission
- imply public columns or client objects are already approved
- approve name-only joins
- mention model/rankings integration as already planned
- send through automation without explicit approval

## Send Record Requirements

When outreach is manually sent later, record:

- provider
- contact
- sender
- exact message artifact used
- date sent
- expected follow-up date
- response-intake owner
- any attachments sent
