# Rights Questions For TruMedia

Ask these questions before accepting or using any sample export, API access, warehouse access, or partner export.

## Access And Product

1. Which product is the correct fit for a private NFL research workflow: NFL Core, NFL Advanced Analytics, NFL API, data warehouse, or partner export?
2. Is a demo or evaluation trial available for a non-team private research tool?
3. If an evaluation is possible, should the first deliverable be a vendor-generated CSV/Parquet export rather than API credentials?
4. Are there user-seat, organization, or affiliation requirements for access?

## Field Rights

5. Can the evaluation export include routes run, route type, targets, receiving yards, air yards/depth, YAC, alignment, snap participation, coverage type, matchup/defender fields, separation/tracking-derived fields, and red-zone context?
6. Which fields are TruMedia-owned, which are third-party fields, and which are derived from NFL player tracking, PFF, SkillCorner, SIS, Sportradar, Stats Perform, or other providers?
7. Which fields are not exportable even if they are visible in the UI?
8. Are precomputed TPRR and YPRR exportable, or should NWR derive them from targets, receiving yards, and routes run?

## IDs And Joins

9. Can the export include GSIS player IDs?
10. Can the export include PFF IDs?
11. Can the export include TruMedia internal player IDs and game/play IDs?
12. Can the export include a crosswalk to Sleeper IDs, or may NWR join Sleeper IDs locally?
13. Are stable game IDs and play IDs available for joins to nflverse or GSIS-derived play-by-play?

## Grains And Coverage

14. Which NFL seasons are available for each requested field family?
15. Which grains are available: play, player-play, player-game, player-week, player-season?
16. Are regular season, postseason, and preseason separated by explicit season type?
17. Are historical schema changes documented by date or schema version?

## Missingness And Zero Semantics

18. For each field, does missing mean unavailable, not applicable, not charted, suppressed by license, or true zero?
19. For routes run, snap participation, targets, red-zone opportunities, and coverage fields, can explicit zero values be distinguished from absent rows?
20. Are there charting delays, corrections, or as-of timestamps for retroactive updates?

## Local Use, Storage, And Derived Artifacts

21. May NWR store the sample export locally outside the production app?
22. May NWR commit compact source-admission receipts, schemas, or aggregate coverage matrices to a private git repository?
23. May NWR store derived artifacts locally if they contain aggregates but not row-level vendor data?
24. May NWR use derived artifacts for private fantasy/dynasty formula research?
25. Is model training, formula tuning, or backtesting allowed under an evaluation license, or only after a full Customer License?
26. Are there retention, deletion, attribution, audit, or redistribution restrictions?
27. May NWR publish no data and keep all results private?

## API And Security

28. If API access is approved, are tokens provided by TruMedia or generated by customer admins?
29. What are the approved secret-handling, rotation, and logging requirements?
30. Are API results allowed to be cached locally for evaluation? If yes, for how long and in what form?
