## Methodology

Every cell distinguishes: **LIVE OBSERVATION (this session)** — an HTTP request this worker made itself today against the real running backend; **LIVE OBSERVATION (carried forward)** — a real live check reported by the 2026-09-22 waiver-night hardening ledger, relayed here but NOT reproduced by this worker today (explicitly marked, never silently treated as equivalent to a fresh check); **INSPECTED CODE** — this worker or a delegated read-only research subagent read the actual source; **INFERENCE** — a reasoned synthesis explicitly flagged as such, never presented as observed fact.

## Status label policy (strict 6-label vocabulary; no other labels used)

- **TRUSTED** — verified correct with no known material gap. *Not used anywhere in this matrix* — every real tool audited carries at least one disclosed or undisclosed gap; forcing a bare TRUSTED anywhere would overstate confidence.
- **TRUSTED_WITH_DISCLOSED_LIMITATION** — live-verified (this session or credibly carried forward) and correct within scope; known gaps exist but are either surfaced to the owner in-product (explicit UI copy/API fields) or are narrow enough (e.g., "no SOS signal," "N/A for this league's config") that they cannot silently produce a wrong-looking-right answer.
- **IMPLEMENTED_UNVERIFIED** — a real, inspected code path exists but was not independently live-exercised by this worker this session (and no credible recent carried-forward live check exists either, or the carry-forward gap itself is being flagged as stale).
- **PARTIAL** — real but materially incomplete, degraded, or carries a gap this worker found that is **not** disclosed to the owner in-product (e.g., a silent-zero-default risk, a missing staleness field, a currently-unconfigured provider key producing an honest-but-non-functional result).
- **BLOCKED** — a real, honest hard failure (409) or architectural gate for this league/provider combination.
- **UNSAFE** — would silently produce a confident-looking wrong answer with no hedge at all. *Not used anywhere in this matrix* — every gap found this pass is either disclosed, honestly hedged (UNAVAILABLE/UNKNOWN/409), or bounded to a narrow edge case; nothing found rises to actively dangerous. This absence is itself a real finding, not an oversight — see the Overall Patterns section.

## Overall patterns found

1. **Where trust is genuinely earned (TRUSTED_WITH_DISCLOSED_LIMITATION), it is earned by real, live-verified behavior plus honest disclosure fields the owner can actually see** — the weekly in-season decision tools (Start/Sit, Waivers, FAAB) for both real Sleeper leagues are the strongest results in this audit: real live data, real governed-model output, real per-response provenance (`dataHealth`, `EXPERIMENTAL_EXTERNAL` labeling, `MANUAL` status labeling), and a real, positive finding that a previously-flagged gap (FAAB percent-of-budget) has since been closed.
2. **The Redraft trade lane (Trade Analysis/Finder/Package Search) is real and functionally live-verified, but is the weakest-disclosed lane of the "already-hardened" tools** — it reuses the same governed `marginal_roster_utility_v2` model as everything else, but uniquely lacks any `dataHealth`/`data_versions` provenance in its decision envelope, and has a real (if narrow) silent-zero-default risk for unranked players that the rest of the app's philosophy (explicit UNKNOWN-not-zero, seen everywhere else including the Dynasty Trade Lab) does not allow elsewhere. This is a genuine, previously-undocumented finding from this cycle, not a re-statement of a known issue.
3. **ESPN (KHA, 403 N 18th) is honestly and consistently BLOCKED, not silently degraded to a wrong answer anywhere observed.** Every ESPN-gated tool either 409s with a clear code/message or (for Data Health specifically) degrades gracefully with explicit `NOT_APPLICABLE`/`LOCAL_ONLY` framing. Nothing fabricates ESPN data. The real gap is capability, not honesty.
4. **A real, currently-live gap was found in the K/DST Streamer that a prior cycle's ledger did not have**: `NWR_FANTASYPROS_API_KEY` is not configured in this dev worktree's runtime today, so the tool honestly returns `UNAVAILABLE` rather than the live picks the 2026-09-22 ledger observed in what must have been a differently-configured environment. This is exactly the kind of thing a "re-verify, don't assume" pass is supposed to catch, and it did.
5. **Profile/League switching has a real, working, load-bearing leakage-prevention mechanism**, but it is a set of ad hoc per-surface guards (refs, a serialization queue) rather than a single structural invariant — the one piece of infrastructure purpose-built to prevent cross-league correlation (`leagueSnapshotId`) is not actually enforced by the frontend, only displayed. No leakage was found in 6 real live switches this session, but the safety net is thinner than the presence of `leagueSnapshotId` might suggest to a future reader of the code.
6. **The Dynasty Trade Decision Lab is architecturally the most rigorous trade-evaluation surface in the entire app** (explicit UNKNOWN-not-zero philosophy, disclosed market staleness, real ownership annotation from a real imported league) — but this cycle could not independently confirm it live because only a `--mode redraft` backend was running. This is the single largest verification gap in this audit and should be closed early by whichever future worker has a `--mode dynasty` instance available.
7. **No UNSAFE finding anywhere.** Every real gap found this pass is either disclosed to the owner, honestly hedged with an explicit UNKNOWN/UNAVAILABLE/409 state, or bounded to a narrow edge case (unranked players in a trade). This is a meaningfully positive finding for a "blind-use readiness" audit, not just an absence of evidence — this worker specifically looked for silent-default and cross-league-leakage failure modes per the dispatch's own checklist and found real, narrow instances of the former (row 10) but none of the latter.
